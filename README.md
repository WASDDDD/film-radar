# 影视雷达

> **这个仓库是静态托管版（GitHub + Netlify）**，和手机本机上跑的完整版是同一套前端与核验逻辑，差别只有三处：
> 1. 片库不再是后台刮削出来的活库，而是随仓库发布的快照 `data/library.mjs`（1784 部，见「静态托管版」一节）。
> 2. 大体积本地 mp4（大雄兔、SINGULARITY、Glass Half 等）已换成 Blender / W3C 的官方直链，仓库里不含任何视频文件。
> 3. `api/*` 由 Netlify Function 代理，检索预算从 20 秒压到 7 秒（函数单次调用上限 10 秒）。
>
> 本机完整版的启动方式仍在下文，`server.mjs` / `service.mjs` / 刮削器都不在这个仓库里。

打开 <http://127.0.0.1:18770/>。在此目录执行以下命令，后台启动并验证健康状态：

```sh
node service.mjs start
node service.mjs status
```

`node service.mjs restart` 重启，`node service.mjs stop` 停止本目录管理的服务。日志为 `service.log`，进程记录为 `service-state.json`；重复 start 不会重复启动。开发时仍可用 `node server.mjs` 前台运行。后台进程不依赖当前终端，但 Android 结束引擎、系统回收或重启手机后需要重新执行 start；未安装系统开机服务。

默认仅本机可访问，不需要安装 npm 依赖。站内播放器不转码，播放时显示源视频的实际分辨率。源文件本身可能已经压缩，「未转码」不等于无损编码或蓝光画质。

## 静态托管版（GitHub + Netlify，2026-11-22 新增）

- 线上地址：**<https://film-radar-wasdddd.netlify.app>**
- 源码仓库：**<https://github.com/WASDDDD/film-radar>**（公开）
- 重新部署：`NETLIFY_AUTH_TOKEN=<令牌> node deploy.mjs`。脚本会打包 `netlify/functions`、上传 `public/` 与函数、轮询到 ready；站点已存在则复用（默认名 `film-radar-wasdddd`，可用参数覆盖）。
- 这个站点当前是**手工 API 部署**：执行一次 `node deploy.mjs` 就更新。想让 `git push` 自动构建，需要在 Netlify 里给该站点安装 GitHub App（授权 `WASDDDD/film-radar`）——没装 App 时 Netlify 的构建会因为拿不到仓库权限报 `Host key verification failed`，走上面的脚本即可，不影响线上。

目录结构：

```
public/                 # 静态站点根目录（index.html / style.css / app.js / catalog.js / assets）
data/library.mjs        # 1784 部刮削片库快照（ES 模块，不再有后台刮削）
data/cntv.mjs           # 央视《探索·发现》1000 期公开节目快照
data/wiki.mjs           # WikiFlix/Commons 3860 部开放电影候选
lib/                    # 与手机版共用的核验模块（SPS 解析、清单核验、检索收敛）
netlify/functions/api.mjs  # /api/* 代理：检索、核验、片库分页全部在这里
netlify.toml + public/_redirects  # /api/* → /.netlify/functions/api/:splat
dev-server.mjs          # 本地预览：按 Netlify 的方式跑 public/ + 同一个函数
```

- **视频全部走远程直链**，仓库 8 MB 左右、不含 mp4。大雄兔指向 `https://media.w3.org/2010/05/bunny/movie.mp4`（完整正片 596 秒），SINGULARITY / Glass Half / Daily Dweebs 指向 `video.blender.org` 的 PeerTube 原文件，寻龙记预告指向 `download.blender.org`。这些都实测支持 Range 请求，可拖动进度。
- **检索与核验逻辑与手机版同一份代码**：`lib/vod-sources.mjs` 原样搬过来，仍然逐条核验清单（`#EXT-X-ENDLIST`、无 DRM、首分片可取、片长门槛），仍按 SPS 实测像素选最高画质档。函数里通过 `lib/function-env.mjs` 把 `VOD_PROVIDERS=ffzy,wujin,modu`、`VOD_DEADLINE_CAP=4000`、`VOD_BUDGET=7000` 压进环境，实测最慢一次检索 7.5 秒。
- **片库是静态快照 + 手动继续刮削**：`data/library.mjs` 是刮削器在手机上跑出来的 1784 部结果。服务器没有可写磁盘，所以静态版的「继续刮削」按钮改成**每次点击现场抓两页上游片单**：`/api/scrape-more?cursor=来源:页码&take=3` 在 6.5 秒预算内拉一页 MacCMS 片单、过滤短剧/漫剧/成人、并发核验 3 部清单，返回可直接播放的条目；浏览器把它们累加进 `localStorage`（`film-radar.extra.v1`，上限 400 条），游标存 `film-radar.scrape.cursor.v1`，刷新后依然在。面板显示「本机 +N / 已入库 1784+N 部」，分类计数同步把新增条目算进去。手机版仍是后台连续刮削，两边互不影响。
- **去掉了 Netlify 免费版的悬浮徽标**：Netlify 会往 HTML 里注入 `<script async src="/.netlify/scripts/hud?variant=public" data-nf-variant="public" …>`，该脚本在 body 里塞一个 `#nl-badge-frame` 的 srcdoc iframe。`netlify.toml` 的 redirect 拦不住这条内部路径（仍 200），所以改在 `public/index.html` 最前面放一段内联脚本：`MutationObserver` 盯 `documentElement` 的 childList+subtree，一旦出现 hud 脚本节点或 `#nl-badge-frame` / `#nl-hud-frame` 立即 `remove()`（脚本靠 `document.currentScript || document.querySelector("script[data-nf-variant]")` 定位，取不到就直接 return），另加 `DOMContentLoaded` 和 800ms 轮询兜底，`style.css` 里再补一条 `display:none!important`。实测线上 `iframes: []`、`hudScripts: 0`，页面完全没有徽标。
- **播放分片不需要代理**：`vip.ffzy-plays.com` 等播放域名实测返回 `access-control-allow-origin: *`，hls.js 直连即可；只有采集站 API 没有 CORS 头，所以检索必须走函数。
- 本地预览：`node dev-server.mjs`（默认 <http://127.0.0.1:18880>），它同时服务 `public/` 和函数，行为和线上一致。
- 部署：Netlify 站点用 `netlify.toml` 的 `publish = "public"`、`functions = "netlify/functions"`，构建命令留空（纯静态 + 预打包函数）。`TMDB_TOKEN` 是可选的站点环境变量，不配就不启用 TMDB 那一路检索。

## 通用片名检索（2026-11-21 新增，当日扩容至 4 条片源并按实测分辨率选线）

- 搜索框现在会并行查询公开片库接口，任意中文片名都能现查，不再只限预置条目。当前接入 **4 条公开 MacCMS 采集源**：非凡资源（api.ffzyapi.com）、无尽资源（api.wujinapi.com）、魔都资源（caiji.moduapi.cc）、北斗资源（api.apibdzy.com）。四条源并行检索、各自先核验再合并，整体耗时由最慢的一条决定，单次检索约 4–15 秒（早期源多在 1 秒内返回，慢源超预算后自动用已核验结果先出页面）。
- 结果只保留通过清单核验的完整正片：HLS 清单必须带 `#EXT-X-ENDLIST`（不是直播或切片）、无 SAMPLE-AES/Widevine/PlayReady/FairPlay 加密、首个分片可取，并且累加 `#EXTINF` 得到的片长达到正片门槛（电影 ≥ 20 分钟，剧集单集 ≥ 10 分钟）。核验不通过的条目直接丢弃，不会以“可能能播”的形式出现。
- **画质按实测像素选线，不按主清单自报值**：主清单常只报 800 kbps / 1080×608，但同目录挂着 `3000k/hls/mixed.m3u8`（非凡）、`1000k_720/hls/index.m3u8`（无尽）、`2000kb/hls/index.m3u8`（魔都）这类高码率子路径。检索时把主清单与这些子路径并发测一遍，用分片里的 H.264 SPS 解析出真实宽高（`sps.mjs`，不依赖 ffprobe），按像素数取最高档；子路径片长要与主清单一致（±5% 或 30 秒内）才算同一部正片，避免把挂载的预告片当正片。分辨率档位按短边判定：长边 ≥ 3400 为 4K、≥ 2400 为 1440P、短边 ≥ 1060 为 1080P、≥ 700 为 720P，竖屏短剧不会冒充 1080P。
- 同一部片跨来源保留多条线路：卡片详情里有「备用线路」，点一下切换（`/api/vod-item` 现取现核验），当前线路失效时不必重新搜。剧集只预先核验第一集，其余分集在点第 N 集时才单独核验并取真实片长；播放器仍在 `loadedmetadata` 用片长守卫复核，长度不符立即拒播并标记该条失败。
- 播放器优先走随站附带的 hls.js：Chromium 对 `application/vnd.apple.mpegurl` 恒答 `maybe`，但不少公开片源的原生解析会直接报 `MEDIA_ERR_SRC_NOT_SUPPORTED`（error 4）黑屏，hls.js/MSE 反而能正常解码。
- 检索质量：上游对片名标点极敏感（「你好李焕英」原词 0 命中、去标点或用「李焕英」才有），所以按「原词 → 去标点 → 末尾 3 字 → 开头 3 字」依次兜底并合并结果。`片名+年份`（`西游记1986`）拆成年份过滤，`片名+季数`（`庆余年2`、`沙丘2`）先按片名检索再按季数筛选。命中正片时丢掉「片名加长」的衍生（搜《狂飙》不再混入《狂飙之浴血玫瑰》，搜《繁花》不再混入《繁花1990》《繁花错》）；语言版（国语/粤语）与季数版保留，它们是同一部片的不同线路。
- 同名多版本排序：名称相关度优先，同一档内先看上游评分再看年份（搜《西游记》时 86 版 9.7 分才是正主）；若标题与查询完全相同的那条像素不到同名家族里最高档的 60%，降一档（低码率老源不占第一张卡）。镜像先按「片名+年份」去重再核验，避免占满名额把别的作品挤掉；年份为空的条目补上同名条目的年份，不会裂成两张一样的卡。

## 影片分类与筛选（2026-11-22 新增）

- 首页在「完整可播片库」标题下有三行筛选：分类（全部 / 剧集 / 电影 / 动漫 / 综艺 / 纪录 / 体育）、地区（全部地区 / 中国 / 欧美 / 日本 / 韩国 / 台湾 / 香港 / 亚洲其他）与画质（全部画质 / 仅高清 1080P+），分类/地区 chip 带实时计数。
- **画质优先选线（2026-11-22）**：同一部片有多家线路时，主线路先按实测像素排序（1080P/4K 压过 720P），画质相同才比集数与评分——此前剧集按集数优先，集数多的 720P 源会顶掉 1080P 源。
- **「仅高清 1080P+」筛选**：点开后片库只显示短边 ≥ 1060 的条目，低清全部隐藏；筛选走服务端 `browse({quality})`，与分类/地区可叠加。源站本身只有 720P 的片（《让子弹飞》《甄嬛传》等）无法凭空提升，选高清后不会出现，这是源站上限而非本站降质。
- 分类与地区在**入库时**就写好（`vod-catalog.mjs` 的 `CATEGORY` / `AREA` 词表，按上游 genres 与 area 归一），所以计数覆盖全库，不只是当前已加载的那几页。
- 官方/站内条目也参与筛选：`categoryOf(x) = x.category || (x.kind === 'tv' ? '剧集' : '电影')`。
- 短剧/漫剧（上游把 3–5 分钟的竖屏短剧标成 movie）在入库阶段按 genres 直接丢弃，避免污染「电影」分类。
- 切换筛选时会重置为 240 张并补拉 6 页，保证分类页不是空的；底部「继续加载」每次 +96 张。

## 自动刮削片库（2026-11-21 新增，2026-11-22 改造）

服务启动 3 秒后自动开始刮削，也可手动控制：

```
curl 'http://127.0.0.1:18770/api/scrape-start'    # 开始/继续
curl 'http://127.0.0.1:18770/api/scrape-stop'     # 暂停
curl 'http://127.0.0.1:18770/api/scrape-status'   # 进度：items/added/rate/cursor/lastError
curl 'http://127.0.0.1:18770/api/scrape-browse?limit=48&page=1&q=&kind=all&category=动漫&region=日本'
```

- 数据源：非凡（ffzy）、无尽（wujin）、魔都（modu）的 `ac=detail&pg=N&pagesize=50` 翻页片单，三源合计约 31.6 万条；北斗（bdzy）无翻页接口，不参与刮削。
- 入库标准与检索一致：标题过滤（解说/预告/花絮/短剧等）、成人内容排除、短剧漫剧排除、`base(title)|year` 去重、首集清单核验（`#EXT-X-ENDLIST`、无 DRM、首个分片可取）、正片时长门槛（剧集单集 ≥600s、电影 ≥1200s）。
- 存储：每条入库即时追加到 `scraped-items.jsonl`（只增不改），游标与 seen 集合写 `scraped-catalog.json`（2 秒防抖 + 原子替换）。这样片库到几万条也不会因为重写整个 JSON 而卡住；重启从 JSONL 恢复。
- 上限由 `SCRAPE_MAX` 控制，默认 0（不限）。启动时设 `SCRAPE=0` 可关闭自动刮削。
- 节奏：每来源每页取最多 20 条、并发 2 条核验、翻页间歇 400ms，实测 20–60 部/分钟；魔都、北斗常超时，超时自动跳到下一页（`lastError` 里能看到）。
- 前端：首页有「LIBRARY HARVEST 片库刮削中」面板，显示入库总数/上限、本轮新增、速度（部/分）、已运行分钟、暂停/继续按钮、各来源与类型的分布；每 5 秒刷新一次。
- 首页「完整可播」计数包含刮削入库条目，网格首批渲染 96 张、「继续加载」每次 +96；页面每 3 分钟自动补拉新入库条目。
- 已验证：刮削入库 1600+ 部时（剧集 600 / 电影 488 / 动漫 274 / 综艺 178 / 体育 121 / 纪录 27），首页计数同步上涨，点开《黑色五叶草 第二季》实测 1920×1080、1449.66s、跳到 80% 正常续播；390px 视口无横向溢出，控制台无报错。

## 借鉴 MIYO 的体验优化（2026-11-22 新增）

根据 `2026-11-22_影视雷达REA/MIYO_REA_影视雷达可复用分析.md`，落地了三条低风险高收益设计（来自 MIYO 静态逆向的设计思路，未复用其代码/密钥/资源）：
- **择优理由（best + reasons）**：vod 详情页「片源说明」上方显示"为什么选这条"，用 chip 标注画质（4K/1080P+/720P）、集数完整度、对比线路数、评分，解释默认线路的选择依据；备用线路仍可一键切换。
- **发现页排序**：首页筛选区加"综合 / 最新上映 / 评分最高 / 集数最多"四档排序，纯前端对已加载片库排序；异常年份（>2027）在"最新上映"里自动排到末尾，避免脏数据抢占首位。
- **继续观看快照建模**：观看进度除资源键外，同时冗余保存片名/分辨率/地区/语言/导演/线路等元数据快照；即使片源缓存被清理或挤出，首页"继续观看"仍能直接渲染标题与画质标签，并从快照恢复条目。

验证：390px 首页四档排序 chip 正常、切换"最新上映"首位为正常年份、0 溢出；vod 详情显示"为什么选这条 / 1080P+ 画质优选 / 已对比 N 条线路"；清空片源缓存后继续观看仍显示标题+分辨率标签；三副本 node --check 通过、0 报错。

## 导入与续播

- 「导入原片」接受本机视频或 HTTPS 视频直链，不接受普通影视详情页。直链由浏览器直接访问；到期的临时地址需要重新导入。
- 本机原片不上传，也不复制进浏览器。刷新后通过「继续观看」重新选择同一个文件即可恢复上次进度。
- 个人导入记录、片单及进度保存在当前浏览器。
